Generated from `backend/prisma/schema.prisma` and verified against the **live** database in the `css-postgres` container (2026-08-24).

- **Database:** PostgreSQL, db `creativesoundstudio`, user `css` (container `css-postgres`)

- **Tables:** 11 app tables (+ 1 Prisma bookkeeping table `_prisma_migrations`)

## How the schema is created and changed

**Prisma migrations are the sole table-creation mechanism.** Nothing creates tables by hand; every table, column, index, enum and foreign key in the live DB originates from a SQL file under `backend/prisma/migrations/`. The backend container runs `prisma migrate deploy` on every boot (compose CMD), so a fresh environment converges to this exact shape automatically. To change the schema: edit `schema.prisma` → `npx prisma migrate dev --name <change>` locally → commit both; deploys apply pending migrations with `migrate deploy`.

## Inspecting the live database

```sh
# list tables
docker exec css-postgres sh -c 'psql -U ${POSTGRES_USER:-postgres} -d ${POSTGRES_DB:-postgres} -c "\dt"'

# describe one table (columns, types, nullability)
docker exec css-postgres psql -U css -d creativesoundstudio -c '\d+ "Booking"'

# all indexes
docker exec css-postgres psql -U css -d creativesoundstudio -c "SELECT tablename, indexname FROM pg_indexes WHERE schemaname='public' ORDER BY 1,2;"
```

(`POSTGRES_USER=css`, `POSTGRES_DB=creativesoundstudio` are set in the container environment.)

## Seed data cross-reference

`backend/prisma/seed.ts` runs automatically after `migrate deploy` in the docker image (and via `npm run prisma:seed`). It is idempotent (find-first/upsert guards):

| Seeded model | Effect | Guard |
| --- | --- | --- |
| User | Upserts 1 admin from `ADMIN_EMAIL`/`ADMIN_PASSWORD` env (bcrypt hash, role `admin`). Skipped if env unset. | upsert by email |
| Service | Creates 10 catalog rows (5 original + 5 "Production" tier), prices "From X RWF". Never updates existing rows. | findFirst by nameEn |
| SiteSetting | Upserts 8 bilingual settings: hero_title (en/rw), about_story (en/rw), contact_email, contact_phone, contact_location (en/rw). | upsert by (key, locale) |
| ClientLogo | Creates 4 logo-wall entries: FAO, The New Times, Kigali Today, Radio 10. | findFirst by name |

Seed does **not** touch Booking, BookingEvent, NotificationLog, PortfolioItem, Testimonial or BlogPost.

Live row counts at generation time: User 1 · Client 36 · Service 10 · Booking 40 · BookingEvent 40 · NotificationLog 134 · PortfolioItem 0 · ClientLogo 4 · Testimonial 0 · SiteSetting 8 · BlogPost 0.

## Entity relationship summary

```
User                     (standalone admin accounts)

Service 1 ────< Booking >──── 0..1 Client      (FK RESTRICT / SET NULL)
                 │

PortfolioItem            (standalone showcase)

Testimonial              (standalone quotes)
SiteSetting              (standalone key/value copy)
```

Arrows read "one side ────< many side"; the FK column always sits on the many side.
